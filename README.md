# TeamFinder — платформа поиска участников проектных команд

Курсовая работа по дисциплине «Проектирование и реализация серверной архитектуры (Django и Flask)»  
**Тема №25:** *Платформа для поиска участников проектных команд (TeamFinder)*.

---

## 1. Назначение проекта и роли пользователей

**TeamFinder** — веб-приложение на базе Django 6.1 и Django REST Framework, разработанное для студентов и преподавателей колледжа. Платформа помогает студентам находить участников своего курса для курсовых, дипломных, лабораторных и хакатон-проектов, общаться внутри проектной команды и обмениваться учебными материалами, а преподавателям и администрации — проверять проекты перед публикацией и подтверждать учебные группы.

### Роли пользователей
- **Гость (неавторизованный пользователь):**
  - просмотр реестра открытых и одобренных проектов на главной странице (`/`);
  - регистронезависимый поиск по названию и описанию, фильтрация по направлению подготовки и требуемому навыку;
  - просмотр паспорта одобренного проекта (`/projects/<id>/`);
  - регистрация студента (`/register/`) и вход в систему (`/accounts/login/`).
- **Студент (`student`):**
  - учётная запись создаётся при регистрации с выбором курса (`1–4 курс`) и учебной группы соответствующего курса; статус группы при регистрации или её смене в профиле устанавливается в *«Ожидает подтверждения»* (`pending`);
  - редактирование профиля (`/profile/`): курс, учебная группа, описание «О себе», выбор своих направлений и навыков (с быстрым фильтром по списку навыков);
  - просмотр индикатора совпадения своих навыков с требованиями каждого проекта (*«Совпадает X из Y навыков проекта»*) и сортировка каталога *«Сначала подходящие по навыкам»* (`?sort=match`);
  - создание собственных проектов (`/projects/create/`), их редактирование (`/projects/<id>/edit/`) и удаление (`/projects/<id>/delete/`), управление лимитом мест (`max_members`, не включая автора);
  - подача заявок на открытые одобренные проекты студентов **своего курса** и отслеживание статусов в разделе «Мои заявки» (`/applications/my/`);
  - управление заявками кандидатов в собственных проектах: принятие (`accept`), отклонение (`reject`) и удаление участника из команды (`remove`) с автоматическим пересчётом свободных мест и статуса набора;
  - участие в закрытом командном чате проекта (`/projects/<id>/chat/`) с обменом файлами (доступно автору проекта и принятым участникам команды);
  - просмотр личных уведомлений (`/notifications/`) и отметка их прочитанными.
- **Преподаватель (`teacher`):**
  - роль назначается администратором через Django Admin; может быть указан куратором учебных групп (`StudyGroup.curator`);
  - доступ к разделу «Модерация» (`/moderation/`) с очередью проектов со статусом *«На проверке»* (`pending`) и списком проверенных проектов;
  - одобрение проекта (`approve`) для публикации в общем каталоге или отклонение (`reject`) с обязательным комментарием-причиной (`rejection_reason`);
  - просмотр паспорта любого проекта и списка поданных в него заявок (преподаватели сами не подают заявки в студенческие проекты).
- **Администратор (`admin` / `is_staff` / `is_superuser`):**
  - управление учебными группами (`StudyGroup`), направлениями (`Direction`), навыками (`Skill`), профилями (`Profile`), проектами (`Project`), заявками (`Application`), сообщениями чата (`ChatMessage`) и уведомлениями (`Notification`) в Django Admin (`/admin/`);
  - подтверждение учебной группы студента (`group_status = 'confirmed'`, включая групповое действие *«Подтвердить учебную группу у выбранных профилей»*) и назначение роли преподавателя;
  - доступ к модерации проектов наравне с преподавателем.

## 2. Основные возможности и структура приложения

### Основные возможности
1. **Профили, курсы и учебные группы (`Profile`, `StudyGroup`):**
   - поддержка 1–4 курсов и учебных групп (по умолчанию миграцией создаются группы `ИС-11`, `ИС-21`, `ИС-31`, `ИС-41`);
   - валидация соответствия выбранной группы курсу обучения при регистрации и редактировании профиля;
   - статус подтверждения группы (`pending` / `confirmed`), изменяемый администратором.
2. **Направления и сгруппированный каталог навыков (`Direction`, `Skill`):**
   - 8 направлений подготовки (*Frontend*, *Backend и API*, *Мобильная разработка*, *UI/UX и графический дизайн*, *Тестирование и QA*, *Данные и ИИ*, *DevOps и базы данных*, *Аналитика, управление проектом и документация*);
   - идемпотентная миграция со стартовым набором из 38 навыков, сгруппированных по направлениям и доступных для редактирования через Django Admin.
3. **Модерация проектов преподавателем:**
   - новые проекты создаются со статусом модерации `pending` (*«На проверке»*) и не отображаются в публичном каталоге и публичном REST API до одобрения (`approved`);
   - при отклонении (`rejected`) преподаватель обязан указать причину, которая отображается автору на странице проекта и в уведомлении; после редактирования отклонённого проекта он автоматически возвращается на повторную проверку (`pending`).
4. **Поиск, фильтрация и подбор по навыкам:**
   - регистронезависимый поиск по названию и описанию проекта (`?q=...`), корректно работающий с кириллицей;
   - фильтрация по направлению (`?direction=...`) и конкретному навыку (`?skill=...`);
   - расчёт числа совпадающих навыков со студентом и сортировка по новизне (`?sort=new`) или по совпадению навыков (`?sort=match`).
5. **Заявки и автоматический контроль мест в команде (`Application`, `Project`):**
   - подать заявку (через веб-форму или REST API) может только студент того же курса, что и автор проекта;
   - лимит мест `max_members` учитывает только приглашённых участников (без автора проекта);
   - метод `sync_recruitment_status()` автоматически закрывает набор (`status = 'closed'`), когда число принятых заявок (`accepted`) достигает `max_members`, и снова открывает набор (`status = 'open'`), если автор удаляет участника из команды.
6. **Командный чат проекта с файлами (`ChatMessage`):**
   - единая переписка команды по адресу `/projects/<id>/chat/`, ссылка «Командный чат» отображается на странице проекта только тем, у кого есть доступ;
   - доступ строго ограничен автором проекта и участниками с принятой заявкой (`status = 'accepted'`); при удалении участника из команды доступ к чату и вложениям сразу прекращается (`403 Forbidden`);
   - поддержка отправки текста, файла или обоих сразу; скачивание вложений через защищённый маршрут `/chat/messages/<id>/attachment/`;
   - ограничение размера файла до **10 МБ** и проверка расширения по белому списку: `pdf`, `docx`, `xlsx`, `csv`, `txt`, `png`, `jpg`, `webp`, `py`, `js`, `ts`, `html`, `css`, `json`, `md`.
7. **Внутренние уведомления на сайте (`Notification`):**
   - отображение счётчика непрочитанных уведомлений в верхней панели навигации на всех страницах и раздел `/notifications/` с действиями «Отметить прочитанным» и «Отметить всё прочитанным»;
   - каждый пользователь видит и изменяет только свои уведомления; защита от дубликатов по ключу события (`event_key`);
   - автоматические уведомления создаются при:
     - отправке нового или отредактированного проекта на проверку преподавателям;
     - поступлении новой заявки автору проекта (через сайт или REST API);
     - принятии или отклонении заявки студента;
     - одобрении или отклонении проекта преподавателем (с текстом причины отклонения);
     - подтверждении учебной группы студента администратором;
     - новом сообщении в командном чате (всем остальным участникам команды и автору проекта, кроме отправителя сообщения).

## 3. Установка и запуск (Python 3.13, окружение `venv313`)

### 1. Подготовка виртуального окружения `venv313` и установка зависимостей
В корне проекта убедитесь, что установлен Python 3.13:
```powershell
py -3.13 --version
```
Создайте окружение `venv313` (если оно ещё не создано) и установите зависимости из `requirements.txt`:
```powershell
py -3.13 -m venv venv313
.\venv313\Scripts\python.exe -m pip install -r requirements.txt
```
*(При желании активировать окружение в текущей сессии PowerShell: `.\venv313\Scripts\Activate.ps1`).*

### 2. Настройка переменных окружения (`.env`)
Создайте в корне проекта файл `.env` с условными значениями (не храните реальные секреты в репозитории):
```env
SECRET_KEY=replace-with-your-own-random-secret-key
DEBUG=True
```

### 3. Применение готовых миграций
Выполните применение миграций базы данных:
```powershell
.\venv313\Scripts\python.exe manage.py migrate
```
*(Миграции `0001`–`0006` создадут таблицы всех моделей, учебные группы `ИС-11`…`ИС-41`, 8 направлений и 38 стартовых навыков по направлениям).*

При необходимости создать учётную запись суперпользователя для входа в `/admin/`:
```powershell
.\venv313\Scripts\python.exe manage.py createsuperuser
```

### 4. Наполнение демонстрационными данными (`seed_demo_activity`)
В проекте предусмотрена безопасная повторно запускаемая команда `seed_demo_activity`, которая создаёт демонстрационные аккаунты с префиксом `demo_` и связанную активность, не удаляя и не изменяя уже существующие пользовательские записи:
```powershell
.\venv313\Scripts\python.exe manage.py seed_demo_activity
```
Что делает команда:
- создаёт (если ещё не существуют) 1 преподавателя (`demo_teacher`, куратор группы `ИС-21`) и 4 студентов (`demo_alikhan`, `demo_ainura`, `demo_bekzat` — 2 курс, группа `ИС-21`; `demo_timur` — 3 курс, группа `ИС-31`);
- при **первом** создании `demo_`-аккаунтов генерирует для них случайные пароли и один раз выводит их в консоль (при повторных запусках пароли существующих аккаунтов не меняются и дубликаты не создаются);
- добавляет 4 реалистичных проекта (два одобренных с открытым набором, один одобренный с полностью набранной командой и закрытым набором, один проект со статусом «На проверке» для демонстрации модерации);
- создаёт заявки со статусами `accepted`, `pending` и `rejected` между студентами одного курса, сообщения в командных чатах и внутренние уведомления.

*(Также при необходимости можно загрузить базовую фикстуру `.\venv313\Scripts\python.exe manage.py loaddata demo_data.json`).*

### 5. Запуск сервера разработки и существующих тестов
Запуск веб-сервера:
```powershell
.\venv313\Scripts\python.exe manage.py runserver
```
- **Веб-интерфейс:** http://127.0.0.1:8000/
- **Панель администратора Django:** http://127.0.0.1:8000/admin/

Запуск существующего набора автоматизированных тестов:
```powershell
.\venv313\Scripts\python.exe manage.py test
```

## 4. Документация REST API

Четыре маршрута REST API реализованы в `teams/api.py` и `teams/serializers.py` и подключены в `teams/urls.py`.

| Метод | Адрес | Права доступа | Назначение |
|-------|-------|---------------|------------|
| `GET` | `/api/projects/` | Все (`AllowAny`) | Список открытых (`status="open"`) и одобренных (`moderation_status="approved"`) проектов |
| `GET` | `/api/projects/<id>/` | Все (`AllowAny`) | Детальная информация об одобренном проекте (`moderation_status="approved"`) по его `id` |
| `POST` | `/api/projects/<id>/apply/` | Авторизованные (`IsAuthenticated`) | Подача заявки в открытый одобренный проект студентом того же курса |
| `GET` | `/api/my-applications/` | Авторизованные (`IsAuthenticated`) | Список заявок текущего авторизованного пользователя |

### 1. `GET /api/projects/`
Возвращает массив всех проектов, у которых одновременно `status="open"` и `moderation_status="approved"`. Проекты, находящиеся на проверке (`pending`), отклонённые (`rejected`) или с закрытым набором (`closed`), в выдачу не попадают.
- **Права доступа:** `AllowAny`.
- **Пример ответа (`200 OK`):**
```json
[
  {
    "id": 2,
    "title": "Интерактивное расписание и карта кабинетов колледжа",
    "description": "Веб-сервис для студентов и преподавателей с удобным расписанием занятий, фильтрацией по учебным группам и поиском свободных аудиторий по корпусам.",
    "owner": "demo_alikhan",
    "required_skills": [
      "Django",
      "Python",
      "React",
      "Figma",
      "PostgreSQL"
    ],
    "status": "open",
    "created_at": "2026-11-10T16:54:18.120000+06:00"
  }
]
```

### 2. `GET /api/projects/<id>/`
Возвращает данные одного одобренного проекта (`moderation_status="approved"`). Если проект не существует или не одобрен модератором, возвращается `404 Not Found`.
- **Права доступа:** `AllowAny`.
- **Пример ответа (`200 OK`):**
```json
{
  "id": 2,
  "title": "Интерактивное расписание и карта кабинетов колледжа",
  "description": "Веб-сервис для студентов и преподавателей с удобным расписанием занятий, фильтрацией по учебным группам и поиском свободных аудиторий по корпусам.",
  "owner": "demo_alikhan",
  "required_skills": [
    "Django",
    "Python",
    "React",
    "Figma",
    "PostgreSQL"
  ],
  "status": "open",
  "created_at": "2026-11-10T16:54:18.120000+06:00"
}
```

### 3. `POST /api/projects/<id>/apply/`
Создаёт заявку текущего студента на участие в одобренном открытом проекте и отправляет внутреннее уведомление автору проекта.
- **Права доступа:** `IsAuthenticated`.
- **Пример запроса (`Content-Type: application/json`):**
```json
{
  "message": "Учусь на том же курсе, готов разработать серверное API и автотесты."
}
```
- **Пример успешного ответа (`201 Created`):**
```json
{
  "id": 8,
  "project": "Интерактивное расписание и карта кабинетов колледжа",
  "message": "Учусь на том же курсе, готов разработать серверное API и автотесты.",
  "status": "pending",
  "created_at": "2026-11-10T18:10:00.000000+06:00"
}
```
- **Возможные ответы с ошибками:**
  - `403 Forbidden`:
    - `{"detail": "Нельзя подать заявку на свой проект"}`
    - `{"detail": "Преподаватели не подают заявки в студенческие проекты"}`
    - `{"detail": "Подать заявку могут только студенты того же курса"}`
  - `400 Bad Request`:
    - `{"detail": "Набор закрыт"}` (если `project.status != "open"` или достигнут лимит `max_members`)
    - `{"detail": "Вы уже подавали заявку"}`

### 4. `GET /api/my-applications/`
Возвращает список всех заявок, поданных текущим авторизованным пользователем.
- **Права доступа:** `IsAuthenticated`.
- **Пример ответа (`200 OK`):**
```json
[
  {
    "id": 8,
    "project": "Интерактивное расписание и карта кабинетов колледжа",
    "message": "Учусь на том же курсе, готов разработать серверное API и автотесты.",
    "status": "pending",
    "created_at": "2026-11-10T18:10:00.000000+06:00"
  }
]
```

## 5. Демонстрационный сценарий проверки

### 1. Регистрация студента и подтверждение учебной группы
1. Откройте страницу регистрации `/register/`, укажите логин, почту, выберите курс (например, **2 курс**) и учебную группу этого курса (**ИС-21**), введите пароль и зарегистрируйтесь.
2. Перейдите в **«Профиль»** (`/profile/`): в карточке пользователя отображается роль **Студент**, группа **ИС-21 (2 курс)** и статус **«Ожидает подтверждения»**. Заполните описание «О себе», выберите свои направления и навыки и сохраните профиль.
3. Войдите в Django Admin (`/admin/teams/profile/`) под администратором, отметьте профиль студента и выполните действие **«Подтвердить учебную группу у выбранных профилей»** (либо переключите поле статуса группы на «Подтверждена» и сохраните).
4. У студента в шапке сайта увеличится счётчик непрочитанных уведомлений, а на странице **«Уведомления»** (`/notifications/`) появится запись: *«Администратор подтвердил вашу учебную группу (ИС-21).»*.

### 2. Создание проекта и модерация преподавателем
1. Под аккаунтом студента откройте **«Мои проекты»** (`/projects/my/`) и нажмите **«+ Создать проект»** (`/projects/create/`).
2. Заполните название, описание, выберите требуемые направления и навыки, укажите количество мест для участников (например, `2`) и сохраните проект.
3. Проект получает статус модерации **«На проверке»** (`pending`), скрыт из публичного каталога `/`, а всем преподавателям автоматически приходит внутреннее уведомление о новом проекте на проверке.
4. Войдите под аккаунтом преподавателя (`role = 'teacher'`) и перейдите в раздел **«Модерация»** (`/moderation/`):
   - откройте проект кнопкой **«Проверить»**;
   - при отклонении укажите текст замечаний в поле «Причина отклонения» и нажмите **«Отклонить проект»** — автор получит уведомление с причиной и сможет отредактировать проект для повторной отправки на проверку;
   - при нажатии **«Одобрить проект»** статус меняется на **«Одобрен»**, автору приходит уведомление об одобрении, а проект сразу появляется на главной странице каталога (`/`).

### 3. Поиск проекта, подача заявки и набор в команду
1. Под аккаунтом другого студента **того же курса** (например, 2 курса) на главной странице (`/`) используйте поиск, фильтр по направлению/навыку и сортировку **«Сначала подходящие по навыкам»**. В каждой записи каталога виден индикатор **«Совпадает X из Y навыков проекта»** и число свободных мест.
2. Откройте страницу проекта (`/projects/<id>/`), заполните сопроводительное сообщение и нажмите **«Отправить заявку»** (студенту другого курса форма недоступна — выводится сообщение об ограничении по курсу).
3. Автору проекта приходит уведомление о новой заявке. На странице проекта в боковой панели **«Заявки»** автор видит карточку кандидата (курс, группа, «О себе», направления и навыки) и нажимает **«Принять»**:
   - кандидату отправляется уведомление *«Ваша заявка на проект … принята!»*;
   - счётчик свободных мест обновляется; когда заняты все места (`accepted_count == max_members`), статус проекта автоматически меняется на **«Набор закрыт»** (`closed`);
   - если автор нажмёт **«Удалить из команды»**, место освободится и статус проекта снова станет **«Набор открыт»** (`open`).

### 4. Работа в командном чате и уведомления
1. На странице проекта у автора и всех участников со статусом заявки **«Принята»** (`accepted`) доступна кнопка **«Командный чат»** (`/projects/<id>/chat/`). Посторонним пользователям и кандидатам с непринятыми заявками чат недоступен.
2. В чате отображаются состав команды, история сообщений по времени и прикреплённые файлы. Участник или автор может отправить текстовое сообщение, прикрепить файл (до 10 МБ, разрешённые форматы) или отправить оба сразу.
3. При отправке сообщения все остальные участники команды (кроме автора сообщения) получают внутреннее уведомление со ссылкой на чат проекта.
4. В разделе **«Уведомления»** (`/notifications/`) пользователь может перейти по ссылке к нужному проекту или чату, отметить отдельное уведомление прочитанным или нажать **«Отметить всё прочитанным»**.
